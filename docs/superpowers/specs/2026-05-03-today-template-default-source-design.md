# Today 页默认展示个人模板设计

## 背景

当前 `today` 页同时存在两套训练来源：

- 系统生成的今日训练方案，作为主训练区内容展示
- 个人训练模板的当日预览，只在“我的训练模板”卡片中展示

这导致用户即使已经保存并启用了自己的模板，主训练区仍然优先显示系统有氧或系统力量方案，形成“上面是我的模板预览，下面还是系统训练”的割裂体验。

本次目标是把 `today` 页的默认主展示切到个人模板，同时保留系统方案作为可恢复的备用来源。

## 用户目标

用户希望在训练模板页生成并保存自己的模板后：

1. `today` 页主训练区默认展示个人模板当天内容
2. 这种默认行为持续生效，而不是只影响当天一次
3. 系统训练方案仍然保留，但退到“恢复系统方案”入口后面
4. 如果个人模板当天是休息日，也严格按模板显示休息/恢复日，不自动回退系统训练

## 非目标

本次不处理以下内容：

- 不新增单独的“训练来源设置页”
- 不支持多模板策略或复杂优先级规则
- 不修改打卡、复盘的业务计算逻辑
- 不改变系统训练生成逻辑本身

## 方案概览

本次采用“后端持久化默认训练来源偏好 + `today` 页按偏好自动切换主展示”的方案。

核心思路：

- 在用户档案层新增长期偏好 `preferredTrainingSource`
- 支持两种取值：`system`、`template`
- `today` 页加载时读取该偏好
- 如果偏好为 `template` 且存在可用启用模板，则主训练区优先展示模板当天内容
- 系统训练方案保留为备用，并提供“恢复系统方案”入口
- 点击“恢复系统方案”会把长期偏好改回 `system`

这样既能满足“默认主展示改成自己的模板”，又能保证刷新、重新登录、跨天进入页面时行为一致。

## 数据模型

### 用户长期偏好

在用户资料模型中新增字段：

- `preferredTrainingSource: 'system' | 'template'`

默认值：

- 现有用户默认为 `system`
- 新用户默认为 `system`

更新时机：

1. 用户在模板页启用模板后，若没有明确切回系统方案，则将该偏好设置为 `template`
2. 用户在 `today` 页点击“恢复系统方案”后，将该偏好设置为 `system`

### today 页视图模型

`today` 页需要明确区分两类内容：

- `systemTrainingPlan`
  始终保留系统原始训练方案，用于备用展示和恢复
- `activeTrainingSource`
  当前主展示来源，取值为 `system` 或 `template`

当 `activeTrainingSource = template` 时：

- 主训练区展示模板当天内容
- 系统训练方案不再抢占主区域

## 页面行为

### today 页加载逻辑

进入 `today` 页时按以下顺序决策：

1. 读取用户 `preferredTrainingSource`
2. 若偏好为 `template`
   - 查找已启用个人模板
   - 根据当前自然日映射到对应星期
   - 生成模板当天预览
3. 若模板当天可用
   - 主训练区展示模板当天内容
   - `activeTrainingSource = template`
4. 若模板不可用
   - 临时回退到系统训练方案
   - 给出提示“当前没有可用模板，已切回系统方案”
   - 后端同步将 `preferredTrainingSource` 改回 `system`

### today 页主展示规则

当偏好为 `template` 时：

- 上方“我的训练模板”卡片继续保留
- 下方主训练区直接展示模板当天内容

训练日：

- 展示模板标题
- 展示动作、组数、次数、备注
- 展示模板对应的训练强度、预计时长等字段

休息日：

- 主训练区显示“休息 / 恢复日”
- 展示恢复说明或备注
- 不自动展示系统训练方案

### 恢复系统方案

保留显式入口：

- `恢复系统方案`

点击后执行两件事：

1. 当前 `today` 页主训练区切回系统训练方案
2. 用户长期偏好 `preferredTrainingSource` 更新为 `system`

这不是一次性的页面切换，而是切回长期默认来源。

## 模板页行为

模板页的关键行为变化如下：

- 当用户保存并启用了模板后，系统应把默认训练来源切到 `template`
- 这样用户回到 `today` 页时，主训练区会自动优先展示该模板

这里的“启用模板”含义保持现有语义，即该模板可参与 `today` 页替换。

## 异常与兜底

### 无启用模板

若偏好为 `template`，但当前没有任何启用模板：

- 回退展示系统方案
- 返回友好提示
- 自动把长期偏好重置为 `system`

### 模板当天为空

若启用模板存在，但当天找不到有效星期配置：

- 视为模板不可用
- 与“无启用模板”走同一回退逻辑

### 模板当天为休息日

此场景不回退系统训练。

处理方式：

- 严格按模板展示休息 / 恢复日
- 仍提供“恢复系统方案”入口，由用户自己决定是否切回

## 后端改动范围

### 数据层

- 在用户资料模型中增加 `preferredTrainingSource`
- 补 migration、schema、DTO 映射和序列化输出

### 服务层

- 在模板启用成功后支持切换默认来源为 `template`
- 提供切回 `system` 的持久化能力
- `today` 数据组装时输出当前主训练来源
- 继续保留系统训练方案，避免丢失恢复入口

## 前端改动范围

### 模板页

- 启用模板成功后，默认训练来源切换为 `template`

### today 页

- 根据 `preferredTrainingSource` 决定主训练区展示模板还是系统方案
- 保留系统方案恢复入口
- 当来源为模板时，主训练区改为模板当天内容
- 当模板当天是休息日时，主训练区展示恢复日内容

## 测试策略

### 后端

- 用户偏好默认值测试
- 启用模板后偏好切换为 `template`
- 恢复系统方案后偏好切换为 `system`
- 偏好为 `template` 但无启用模板时自动回退

### 前端

- `today` 页在 `template` 偏好下优先展示模板主内容
- `today` 页在 `system` 偏好下继续展示系统训练
- 模板休息日展示恢复态，不自动回退系统训练
- “恢复系统方案”后主展示和来源偏好同步切换

### Smoke 回归

- 锁住 `today` 页模板优先展示文案和恢复入口
- 锁住模板页启用后会切换默认来源的关键行为

## 风险与约束

### 风险 1：前后端状态不一致

如果只做前端切换，不做后端持久化，会导致刷新或重新登录后丢失偏好。

本次方案通过后端字段持久化规避这一风险。

### 风险 2：无模板时反复进入错误状态

如果偏好仍写着 `template`，但模板已被停用或不存在，页面会持续进入无效状态。

本次方案在发现模板不可用时自动回退并修正偏好。

### 风险 3：休息日与系统训练冲突

用户已明确要求严格按模板执行，因此休息日不自动回退系统方案，避免系统替用户做决策。

## 推荐实现顺序

1. 后端新增 `preferredTrainingSource` 字段与 migration
2. `today` 接口补齐来源偏好输出和回退逻辑
3. 模板启用链路接入默认来源切换
4. 前端 `today` 页切换主展示逻辑
5. 增加恢复系统方案的持久化回写
6. 补测试与 smoke 回归
