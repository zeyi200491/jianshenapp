# 训练模板文字导入改版设计

## 目标

把当前“先保存模板，再进入文字导入抽屉，再解析并覆盖已保存模板”的流程，改成更符合用户预期的“粘贴文字直接生成未保存草稿模板”流程。

用户完成链路应变成：

1. 点击 `文字导入`
2. 在弹窗中粘贴训练文字
3. 点击 `生成草稿模板`
4. 系统把文本解析成一份新的未保存草稿模板
5. 主编辑区切换到这份草稿
6. 用户继续手动调整
7. 用户点击 `保存模板` 后才正式落库

本次改动还要保持两个已经确认的 UI 简化要求：

1. 训练日不再暴露“时间”输入框
2. 动作不再暴露“动作编号 / 动作编码”输入框

## 非目标

本次不做以下内容：

1. 不把文字导入结果直接写入数据库
2. 不增加“导入历史”“草稿历史”“撤销栈”这类额外模块
3. 不重写后端解析规则，只复用现有解析接口能力
4. 不在弹窗内实现完整模板编辑器
5. 不改动模板列表的业务定义，左侧列表仍只显示已保存模板

## 现状与问题

当前项目已有这些基础能力：

1. Web 端个人训练模板页已经支持新建、编辑、保存、启用、设为默认模板
2. 后端已经提供文字解析预览接口与应用接口
3. 前端已有文字导入抽屉组件和模板编辑器

当前问题在于交互模型不符合用户心智：

1. `文字导入` 依赖模板先保存，导致入口在草稿阶段不可直接使用
2. 导入流程强调“覆盖已保存模板”，而用户要的是“先生成一份新草稿”
3. 用户无法把文字导入当成“快速建模板”的起点，只能把它当成“改已有模板”的工具
4. 编辑器里仍暴露时长输入和动作编码输入，增加无意义操作成本

## 设计结论

### 1. 文字导入改为“生成草稿模板”能力

`文字导入` 的职责不再是“修改线上模板”，而是“生成一个新的本地草稿”。

改版后：

1. 导入前不要求已有模板 ID
2. 导入后不立即创建数据库记录
3. 导入结果直接进入当前编辑区，作为一份新的未保存草稿
4. 是否正式落库，由用户点击 `保存模板` 决定

这使导入入口和“新建模板”形成同一层级：

1. `新建模板` 是空白起草
2. `文字导入` 是文本起草

### 2. 导入入口使用弹窗，而不是内嵌或抽屉

用户已明确选择弹窗模式。采用弹窗的原因是：

1. 心智更明确，用户会把它理解成“一次性生成草稿”的动作
2. 不会长期占用主编辑区布局
3. 更适合在生成前做“替换未保存内容”的确认
4. 弹窗关闭后，用户能立刻看到主编辑区已被新草稿替换

弹窗中的主按钮统一改成 `生成草稿模板`，不再使用 `开始解析` 或 `确认覆盖` 作为最终动作名称。

### 3. 生成结果是“未保存草稿模板”，不是“已保存模板”

系统内部需要明确区分两类数据：

1. 已保存模板
   - 有真实 `id`
   - 来自后端列表和详情接口
   - 会显示在左侧模板列表

2. 未保存草稿模板
   - 没有真实 `id`
   - 只存在于当前前端编辑区
   - 来源可能是空白新建，或文字导入生成
   - 不会出现在左侧模板列表

文字导入的输出必须是第二类。

### 4. 生成草稿前需要保护未保存内容

如果当前编辑区已经有未保存改动，再点击 `文字导入` 时，必须先弹确认框：

`继续后会替换当前未保存内容，是否继续？`

用户选择：

1. 取消：不打开弹窗，保留当前编辑区
2. 继续：进入文字导入弹窗

这条规则既适用于：

1. 新建空白模板后还未保存
2. 编辑已保存模板但做了未保存修改
3. 刚导入生成过一份草稿，又想再次导入新文本

### 5. 训练时长和动作编码改为系统维护字段

后端当前仍要求训练日带 `durationMinutes`，动作带 `exerciseCode`。因此本次不删除这两个字段本身，只删除用户输入入口。

具体策略：

1. 训练时长
   - 编辑器中不再显示“时间 / 时长”输入框
   - 保存前由前端统一补默认值
   - 休息日仍写入 `null`

2. 动作编码
   - 编辑器中不再显示“动作编号 / 动作编码”输入框
   - 当用户填写动作名称时，前端根据动作名称自动生成内部编码
   - 如果名称为空，则在保存校验阶段拦截

这样可以保持后端兼容，同时把复杂度从用户界面移走。

## 用户流程

### 1. 正常导入

1. 用户进入个人训练模板页
2. 点击 `文字导入`
3. 弹出导入弹窗
4. 用户粘贴训练文字
5. 点击 `生成草稿模板`
6. 前端调用后端解析预览接口
7. 前端把预览结果映射成一份新的本地草稿模板
8. 弹窗关闭
9. 主编辑区显示这份新草稿
10. 页面提示：`已根据文本生成新的草稿模板，你现在可以继续调整后再保存。`

### 2. 当前有未保存修改时再导入

1. 用户已在编辑区做了未保存改动
2. 点击 `文字导入`
3. 页面先弹确认框：`继续后会替换当前未保存内容，是否继续？`
4. 用户确认后，才进入导入弹窗
5. 后续流程与“正常导入”一致

### 3. 导入后保存

1. 用户在草稿模板上继续修改
2. 点击 `保存模板`
3. 如果草稿没有 `id`，调用创建接口
4. 如果是已有模板详情改出来的草稿，仍走更新接口
5. 保存成功后，左侧模板列表刷新并选中最新模板

## 数据与状态设计

### 1. 前端状态

训练模板页至少维护以下状态：

1. `templates`
   - 已保存模板列表

2. `selectedTemplateId`
   - 左侧当前选中的已保存模板 ID

3. `draft`
   - 当前编辑区草稿
   - 可能是已保存模板的可编辑副本，也可能是未保存草稿

4. `importModalOpen`
   - 导入弹窗开关

5. `importRawText`
   - 用户粘贴的原始文本

6. `importPreview`
   - 解析预览结果

7. `draftDirty`
   - 当前编辑区是否有未保存改动

### 2. 草稿生成规则

导入生成草稿时：

1. 使用解析预览结果构建完整的 7 天模板草稿
2. 仅当某些周几被识别到时，替换这些天的内容
3. 未识别到的天，采用空白模板默认结构
4. 休息日写成 `dayType = rest` 且 `items = []`
5. 训练日写成 `dayType = training`
6. `durationMinutes` 仍写入默认值，但不展示给用户
7. `exerciseCode` 通过匹配结果或动作名称自动生成

### 3. 与后端接口的关系

本次不直接调用“确认覆盖模板”的应用接口来落库。

实际使用方式调整为：

1. 继续使用后端“解析预览”接口获取结构化结果
2. 前端把预览结果转换为草稿模板
3. 保存时再走现有 `createTrainingTemplate` / `updateTrainingTemplate`

也就是说：

1. 后端负责解析
2. 前端负责生成草稿
3. 保存动作负责落库

## 组件与职责

### 1. 模板页容器

`apps/web/app/account/training-templates/page.tsx`

职责：

1. 管理模板列表、当前草稿、保存动作
2. 管理导入弹窗的打开、关闭、确认替换
3. 在导入成功后把预览结果映射成草稿
4. 控制提示文案

### 2. 模板编辑器

`apps/web/components/web/training-templates/training-template-editor.tsx`

职责：

1. 展示当前草稿
2. 提供 `文字导入` 按钮
3. 提供 `保存模板` 按钮
4. 不再展示手动时长输入
5. 不再展示动作编码输入

### 3. 文字导入弹窗

新职责：

1. 承载文本输入
2. 展示解析状态与问题提示
3. 点击 `生成草稿模板` 后，把解析结果回传给页面容器
4. 不负责正式落库

## 异常处理

### 1. 空文本

提示：

`请先粘贴训练文字，再生成草稿模板。`

### 2. 文本无法识别

处理：

1. 弹窗不关闭
2. 当前编辑区不被替换
3. 展示提示：
   `这段文字还没法生成模板，请检查周几、动作和组次数写法。`

### 3. 部分识别成功

处理：

1. 允许生成草稿
2. 成功提示改成：
   `草稿模板已生成，部分动作需要你手动补充。`

### 4. 生成后未保存

页面顶部提示：

`当前是未保存草稿，确认无误后再保存模板。`

## 风险与控制

### 1. 前端草稿结构与后端预览结构不一致

风险：

导入结果映射错误，导致草稿展示与最终保存不一致。

控制：

1. 单独抽出“预览结果 -> 草稿模板”的映射函数
2. 为映射函数加定向断言

### 2. 导入生成草稿后覆盖用户当前编辑内容

风险：

用户误丢未保存工作。

控制：

1. 导入前必须确认替换
2. 取消时不做任何状态变更

### 3. 去掉时长与动作编码输入后导致保存失败

风险：

后端仍需要字段，但前端未正确补值。

控制：

1. 保存前统一做草稿归一化
2. `durationMinutes` 自动补默认值
3. `exerciseCode` 自动按动作名称生成

## 推荐实施顺序

1. 先把文字导入的目标文案改成“生成草稿模板”
2. 把导入入口从“依赖已保存模板”改成“允许直接打开”
3. 增加“未保存内容替换确认”
4. 复用后端预览结果生成前端草稿
5. 删除编辑器里的时长输入和动作编码输入
6. 增加保存前归一化逻辑
7. 跑前端源码回归、类型检查和构建验证

## 自检结论

1. 本设计没有保留 `TODO`、`TBD` 或模糊占位词
2. “生成草稿”和“正式保存”的边界明确，不相互混淆
3. 范围聚焦在个人训练模板页，未扩散到无关模块
4. 与用户确认过的三个关键决策已全部固化：
   - 弹窗生成草稿
   - 生成后替换当前编辑区
   - 若有未保存改动则先确认
